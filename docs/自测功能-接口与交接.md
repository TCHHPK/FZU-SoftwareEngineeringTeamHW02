## 二、四个接口

统一返回 `{code, message, data}`；鉴权用 Cookie 或 `Authorization: Bearer <token>`。

### 1. 组卷

```
POST /api/self-tests
{ "session_id": 11, "question_count": 5, "scope_text": "" }

→ 202 { "code":0, "message":"已创建，正在出题",
        "data": { "test_id": 3, "status": "draft", "question_count": 5 } }
```

出题在后台执行（可能调用模型），接口立刻返回。前端轮询第 2 个接口直到 `status = ready`。

### 2. 取卷

```
GET /api/self-tests/{test_id}
```

- `status = draft`：还在出题
- `status = ready`：可作答，**items 里没有 answer / analysis**
- `status = graded`：已判分，items 里补上 `answer`、`analysis`、`user_answer`、`is_correct`

### 3. 交卷

```
POST /api/self-tests/{test_id}/submit
{ "answers": [ { "item_id": 11, "answer": "B" }, { "item_id": 12, "answer": "A" } ] }

→ 200 { "code":0, "message":"已判分", "data": {
        "score": 66.67, "total_score": 100, "correct_count": 2,
        "wrong_count": 1, "status": "graded",
        "items": [ ... 含 answer / analysis / is_correct ... ] } }
```

规则：

- **幂等**：已判分的卷子重复提交，直接返回上次结果，不重复加分、不重复记错题；
- **空答案不报错**：未作答按错处理；
- **一个事务**：分数、逐题结果、错题回填同进同退。

### 4. 列表

```
GET /api/self-tests?limit=50
```

## 三、和另外三个人的接口约定

### 给陈瑀涵（Agent 出题）

`app/services/quiz.py` 里的 `_agent_items()` 是钩子，会尝试：

```python
from app.agents import quiz
items = quiz.generate_quiz_items(conn, session_id=..., knowledge_points=..., count=...)
```

你只要按下面的结构返回，就会**自动接管**出题，我这边的接口一行都不用改：

```python
[
  {
    "knowledge_name": "等价类划分",
    "stem": "关于等价类划分，下列说法正确的是？",
    "options": ["A 文本", "B 文本", "C 文本", "D 文本"],  # 纯文本，字母我会自己加或不加都行
    "answer": "B",                                        # 必须是 A/B/C/D
    "analysis": "解析……",
    "evidence_chunk_key": "d1-p12-c2",
    "evidence_page": 12,
  }
]
```

返回不合格（缺 stem、answer 不是 ABCD、选项少于 2 个）的题目会被丢弃，不影响接口可用性。
模块不存在或抛异常时，自动退化到「用知识点定义反向构造选择题」的兜底算法，**题目同样出自原文**。

### 给沈文驰（错题本）

你的数据已经由交卷过程写好了，直接查 `wrong_questions` 即可：

| 字段 | 含义 |
| --- | --- |
| `knowledge_name` | 已清洗过的知识点名（用于薄弱度聚合，稳定） |
| `source_type` / `source_id` | `self_test` + `self_test_items.item_id` |
| `wrong_count` | 累计答错次数（重复答错累加，不会产生新行） |
| `correct_streak` | 连续答对次数（重做答对 +1，答错清零） |
| `mastered` | 0/1，你按「连对 2 次」置 1 |
| `evidence_chunk_key` / `evidence_page` | 出处，供「定位原文」 |

去重靠唯一键 `(user_id, source_type, source_id)`，你在重做接口里更新 `correct_streak` / `mastered` 即可。

### 给陈佳慧 / 蔡靖熹（前端）

页面状态机：

```
点「开始自测」→ POST /api/self-tests → 拿 test_id
  → 轮询 GET /api/self-tests/{id}，直到 status=ready
  → 渲染 items（只有题干与选项）
  → 交卷 POST .../submit
  → 用返回的 items 渲染对错、正确答案、解析、出处页码
```

未判分时**不要期待 answer 字段**，它在判分后才出现——这是故意的，答案不下发前端。

## 五、已知限制（写清楚，别让人踩）

1. **兜底出题是"模板题"**，不是真·AI 出题。它的价值是让接口先跑通、并且保证题目出自原文；
   真正的题目质量取决于 `app/agents/quiz.py`（陈瑀涵）。
2. **简答题未实现**：`question_type` 支持 `short`，但判分规则里简答按完全匹配处理，
   实际只启用 `single`（判断题结构已就绪，未出题）。
3. **出题在后台**：如果进程在出题中途重启，该卷会停在 `draft`；需要重新组卷。
   未做"启动时把残留 draft 置失败"，属于下期优化。
4. **答案在服务端明文存储**：课程项目规模可接受；若要做防作弊，应存答案哈希并单独校验。
